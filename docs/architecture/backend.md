# Backend modules

- `server.py`: routes. Big payloads (replay, telemetry, live) go out through `raw_json`, skipping FastAPI's slow `jsonable_encoder`. Table endpoints all return `{columns, data, total}` (capped at `MAX_ROWS`), which the data explorer renders generically. `race_info()` (Jolpica race row incl. circuit lat/long) feeds the track and replay routes. Usage counts: `POST /api/count/{event}` (only names in `EVENTS`; `util.js` `count` sends just the name by `sendBeacon`, not at all under Do Not Track / GPC) adds to per-day totals in `.cache/counts.json`, read back at `GET /api/counts`; no id, cookie, IP or URL is kept (a foreign `Origin` gets 403). `GET /api/live/status` says whether a session is on without opening or holding the F1 feed: `app.js` `checkLive` polls it. `check_season` bounds url years and rounds.
- `assets.py`: `static/assets`. `core` (three.js, shaka, fonts, flags; 5 MB) on the first `/` of a process, which answers 503 if it can't; `start`/`status` (`/api/assets`, `POST /api/assets/download`, same-origin only) the optional ~600 MB of 4k skies, textures and `tile_list.json`'s tiles, resumable, from `downloads.js`'s Download assets button in the top bar (and the command palette), which reads Assets ready once nothing's missing, as in a built exe. Until then `scene3d.js` and `textures3d.js` stream Poly Haven's 1k files and `satellite.js` `fetchTile` asks Esri.
- `ledgers.py`: `/api/stationary` (OpenF1 `stop_duration`, partial coverage) and `/api/overtakes` (OpenF1 `overtakes` with the stops and race control to classify them; 3 requests without a cached replay), both opened only from the Results tab's sections.
- `jolpica.py`: Jolpica via basef1 (`jolpica_client`, the same client livef1 bundles; livef1 itself, and pandas with it, load only on the first old-season session table, `server.py` `season`, which keeps a second off every start; tables are flattened by `server.py` `table`). `JOLPICA` maps each kind to a query method and the JSON path to one row; `jolpica_fetch` pages through the 100-row limit; `races(year)` is the cached season race list (`race_info`, the circuit selector, elevation, session list; Jolpica allows ~500 req/h). Past seasons and races over 3 days old go through `SETTLED`, a basef1 client with a disk cache (`.cache/jolpica.sqlite`); the rest through `jolpica_client` (5 min in-memory cache).
- `tracks.py`: outlines from MultiViewer (`MV_KEYS` maps Jolpica circuitId -> MultiViewer key; same coordinate system as OpenF1 car positions), else the elevation's OpenF1 lap (`lap_track`, `source: "openf1"`: Madring, Sepang; no corner numbers), else nearest GeoJSON circuit by lat/long (local metres, unknown start/direction). `circuits.js` `f1Coords` tells the first two apart from GeoJSON. `WIDTHS` adds an approximate track width (m) per circuit. `_clean_loop` drops sub-metre duplicate points and the tail where MultiViewer's lap overlaps its start (both made false hairpins). Track dicts carry `circuitId` and MultiViewer `pitLoss`.
- `replay.py`: `mode: "gps"` for 2023+ from OpenF1 (location resampled to a 0.5 s grid, event feeds sorted by time for binary search in the browser; finished sessions cached in `.cache/replay/{session_key}.json` — delete these after changing the payload format; every cache file goes through `save()` (atomic tmp + replace), and `REPLAY_LOCKS` makes a second request for a session being built wait for it). `mode: "laps"` for 1996+ races from Jolpica cumulative lap times. OpenF1's free tier is ~30 req/min, which `_throttle` in `openf1()` holds to for the whole process; a GPS replay costs ~30 requests, and a session under 2 h past its end is kept in memory for 5 min (`_recent`) since it isn't saved to disk. While any session is live OpenF1 answers 401 to everything (`OpenF1Locked`): season meetings/sessions lists are kept in `.cache/openf1/` as a fallback, `/api/season` falls back to livef1's table, `/api/replay` answers 409 `LIVE_NOW` when the live feed is running that session (replay.js then opens the live view). `server.py` `warm_up` (a background thread at start-up, `__main__` and the f1-test launch config) fetches what the default page asks for on parallel threads (season list, this season's calendar and sessions, the latest race's track/geo/elevation/results: 0.5-2.5 s each cold, which the page used to wait on one after another) and builds the GPS replays of the season's last 3 races (newest first, one at a time for OpenF1's rate limit), so they don't wait ~40 s on first ▶. For any other 2023+ race, `replay.js` `loadData` plays the lap-timing replay (`/api/replay/...?laps=1`) when GPS hasn't answered in 1.5 s, and `swapToGps` takes over at the same race moment when it lands. `/api/telemetry` takes the replay's `start`/`duration` so the replay isn't rebuilt per driver. `elevation()` (`/api/elevation/{year}/{round}`): OpenF1 location z (decimetres) on a fast race lap at that circuit (2023+), cached in `.cache/elevation/{circuitId}.json`. `/api/circuit/{circuitId}` gives the latest past race there (the circuit selector simulates it). `/api/geo/{year}/{round}`: the circuit's real outline in local metres (`tracks._geo_track`, GeoJSON) for georeferencing the satellite ground.
- `f1tv.py`: F1 TV, MultiViewer-style. `/api/f1tv/{year}/{round}`: the weekend's videos from the public catalogue search (`filter_Meeting_Name`, falling back to `MEETING_ALIASES` (Jolpica's Brazilian = F1 TV's São Paulo) and a 6-letter name stem when F1 TV names the meeting differently, e.g. "Malaysia"; 404 = no results; registered after the routes below or it catches them). `/api/f1tv/channels/{id}`: feeds + driver onboards (`additionalStreams`; INTERNATIONAL goes out as channelId null, the content's own feed, since 2024-and-older races refuse it by channelId). `/api/f1tv/play/{id}?channel=`: `CONTENT/PLAY` with the caller's subscription token (`X-F1-Token` header, see `live.py`) as `ascendontoken`, giving a signed DASH manifest (replays: no DRM; the CDN allows localhost origins) that `multiviewer.js` plays with shaka-player (`shaka-player.compiled.js` from jsDelivr, pre-loaded when the Stream page opens) under our own control bar (`tvcontrols.js`: seek with buffered range, ±10 s, volume, speed, captions, PiP, tile fullscreen, k/space/←/→/m/f keys). Start-up tuning in `load`: `manifest.dash.ignoreMinBufferTime` (F1 TV says minBufferTime 30 s, which held the first frame for ~6 × 5.8 s segments: 12 s → 2 s), `player.load(url, startTime)` so a joining tile doesn't fetch the session's start, and the main feed's play request sent alongside the channel list. Quality: every tile plays its highest rendition from the first segment and never steps down (the user's choice: a slow connection buffers instead): ABR off with `defaultBandwidthEstimate` 1e9 so shaka's first pick is the top, then `lockTop` selects it in the tile's ⚙ menu; picking Auto there turns ABR (sized to the tile) back on. F1 TV hands out CDNs at random per play; `f1prodlive.akamaized.net` refuses localhost origins (shaka 1002), so `play` asks again until it gets formula1.com's. 4K (on by default, off where the decoder check fails or the user switched it off): `play(..., uhd=True)` sends `x-f1-override-video-stream: HDR_UHD_DASH` (the header F1 TV's web player's developer settings use), (only 2025+ videos have 4K rights; older ones refuse it, and `play` retries in HD, where they come back as HLS H.264 up to 1080p), which adds 1620p/2160p50 (HEVC Main10, 15.4 Mb/s, main feed only, no DRM on replays); the viewer's 4K switch also sets `preferredVideoCodecs: ['hvc1.2']`, since shaka keeps one video set and otherwise picks the cheaper HEVC Main one (max 1620p), so `lockTop` reaches 2160p on the feeds that have it (`hasUhd`: INTERNATIONAL, F1 LIVE; tracker, data and onboards stop at 1080p); `.mvtile.uhd` shows a 4K badge, and a 4K feed in HD says why beside its quality. Several 4K tiles (measured: 3 x 2160p50 + an onboard, 0-0.1 % frames dropped): 4K tiles keep `bufferBehind` 12 s (not 30), the telemetry overlay only touches the page when its 0.5 s sample changes and is placed on the picture by CSS container units (`.mvtel`, assumes 16:9) instead of reading tile sizes every frame, and opening the viewer closes the other panels (`f1:panel`) and stops the 3D stage behind it (`covered()`). Beyond that it's bandwidth: ~15.4 Mb/s per 4K stream. The button disables itself where `mediaCapabilities.decodingInfo` says HEVC Main10 2160p50 can't be decoded (Firefox, Chrome without GPU HEVC). The viewer opens on one stream; Add stream (popover of feeds + driver cards) adds any number. Design (the user's brief: broadcaster-grade, after Apple TV's multiview): `arrange` places every tile in pixels as a true 16:9 rectangle, grid (the column count giving the biggest tiles, rows centred) or focus (one big, the rest as thumbnails beside or under it, whichever leaves it bigger), re-run by a ResizeObserver and animated by CSS; one header row (close, title; layout switch and Sync only once there are two streams, Teams, Add stream, More), the rest in popovers that `anchor` places under their button: Teams (a card per team; `teamView`: the race feed big + that team's two onboards, Apple's preset) and More (play/pause all, jump to the start, the 4K switch, telemetry sync, the account); per tile, a team-colour label chip that opens the stream picker to switch that tile (it ticks what's on screen and marks this tile's stream), and radio / settings / focus / remove icons that, like the control bar, only show while the mouse moves; the tile you hear has a white ring (bright for a moment as it changes). One line-icon set (`tvcontrols.js` `icon`), no emoji; red only for LIVE; the system UI face. The clicked tile has the sound and is what Sync / Play all follow; a new tile starts at the selected tile's time and catches up once playing. `remember` keeps where the lead tile of a replay got to (localStorage `f1tv-watch`, from 30 s in, every 10 s and on close) for Stream's Continue watching and resume. Each tile's ⚙ lists every rendition (`renditions`: resolution, bitrate, codec; shaka only offers the codec family the browser plays) and audio track (commentary languages, `fx` = track sound, `tea` = team radio on onboards; all 192 kb/s stereo), with ABR `restrictToElementSize` on Auto; `/api/f1tv/account` says whether the caller's token is a live subscription, never the token. `/api/f1tv/telemetry/{year}/{round}/{driver}?session=` (`replay.session_telemetry`: the whole session ±, cached under its own `_tv` tag since `telemetry()`'s cache ignores the start) feeds each tile's see-through overlay (`.mvtel`). F1 TV replays have no clock (static DASH from 0 s, no prft/PDT in any platform variant), so `multiviewer.js` puts video 0 s at F1 TV's scheduled start − `LEAD` (308 s, measured on the 2026 US GP race) plus a per-video offset in localStorage, set with the header's ±1/10 s nudges or 🏁 Lights out (`launchAt`: first launch after 5 s stood still); tested in `tests/test_multiviewer.mjs`. Live = inside the session's scheduled times + 30 min (F1 TV's `state` field is stale); live streams are Widevine (streamType `SDR_HD_DASHWV`): the licence request goes through `/api/f1tv/license` (`f1tv.license`, F1 hosts only) with `ascendontoken` + `entitlementtoken`; tested on Mexico FP1 2026, where F1 TV sent every feed in HD only (`HDR_UHD_DASH` and the guessed `HDR_UHD_DASHWV` both answered HD).
- `radio.py`: team radio for the F1 TV viewer's driver onboards (`/api/f1tv/radio/{year}/{round}?session=[&driver=]`: every driver's clips, each with its `driver`, plus `drivers` (code, name, team, colour, F1 headshot) from the live feed's `DriverList` (`live.driver_list`) or OpenF1 `drivers`). Nobody publishes words, only clips (F1's live `TeamRadio` captures are just Utc, RacingNumber, Path): OpenF1 `team_radio` once a session is over, `live.py`'s `TeamRadio` while it's live (OpenF1 is locked then). A message is timed from its recording start (`started`: the clip's file name holds it in circuit local time; F1 publishes ~30 s later). The audio is on F1's livetiming `/static`, which has answered 401 without sign-in (Oct 30 2026, outside a session) and 200 (Mexico FP2, live), so it's fetched with the caller's F1 TV token as Bearer when there is one, for transcription and for `/api/f1tv/radio/audio?u=` (clips only; registered before `/api/f1tv/{year}/{round}`). Words (`TRANSCRIBE`) from NVIDIA Parakeet TDT 0.6B v3 (the user's pick) as ONNX (`istupakov/parakeet-tdt-0.6b-v3-onnx`) through onnx-asr on the CPU, full precision (~1.4 s an 8 s clip; the int8 build garbled radio), downloaded only when the radio panel's Download button asks (`POST /api/f1tv/radio/model`, `radio.fetch_model`; the payload's `model` says ready / missing / downloading / failed) into `.cache/parakeet/` (~2.5 GB; ONNX Runtime refuses the encoder's external weights from the Hugging Face cache's linked blobs); `decode` resamples with PyAV; one background thread, cached per clip in `.cache/radio/parakeet/`. `radiopanel.js` (the user's design: one radio box for the whole field, not one per onboard): the viewer header's Radio button (unread count) opens a see-through glass panel over the streams, clearer while the mouse is elsewhere; driver profiles in a grid (headshot in a team-colour ring, code, count; glows `FRESH` s after they speak, pulses on air), a card plays that driver's latest message and filters the list to them; then the messages newest first (`radioList`: said by the playhead of `ref()`, the stream Sync follows, so a replay's grows as it plays); Auto-play for new ones; a playing clip ducks the stream you hear to 25 % (`multiviewer.js` `duck`). The user asked for a list, not captions over the picture. Onboards open on their `tea` (team radio) audio track.
- `desktop.py`: the desktop launcher (pywebview, WebView2 on Windows). Starts `server.app` + `warm_up` on threads unless a server already answers on `PORT` (8086, `LIGHTSOUT_PORT`), then the launcher: a frameless 460x560 window on `static/launcher.html` (the app's glass, LO badge, Titillium and ambient light, light/dark with the system; its own title bar: `pywebview-drag-region` with close / minimise buttons calling `Api.quit` / `Api.minimize`) offering Open in the app (`Api.open_app` opens the app in a framed, maximised window of its own with the same `js_api`, then closes the launcher: the launcher itself is frameless, so the app can't live in it) or Open in the browser (`webbrowser.open`; the launcher stays as the stop switch, with another tab / the app instead / Quit). `Api.f1tv_login`: account.formula1.com in a second window, `evaluate_js` polled every 1 s for the `login-session` cookie (`token_of`; the account site is a single-page app, so no load event comes after signing in), then the window closes and the token goes back to `multiviewer.js` `connectPanel`, which shows a Sign in to F1 TV button instead of the bookmarklet when `window.pywebview` is there. Private mode (the default): nothing outlives the app. A windowed exe has no stdout (uvicorn's formatter calls isatty), so it logs to `lightsout.log` beside the exe. `scripts/build_exe.py`: PyInstaller onedir with the icon `static/lightsout.ico` (the LO badge in the app's red and Titillium Web, five unlit start lights from 48 px up, 16-256 px; the windows and taskbar take it from the exe) (`dist/LightsOut/`; onefile would unpack ~450 MB per launch and put `.cache` in %TEMP%), `static` as data, `--collect-all` onnx_asr/livef1. WebView2 isn't officially supported for Widevine: live F1 TV in the app is untested.
- `live.py`: free live timing over F1's SignalR Core feed (`/signalrcore`, no login). One background connection, opened by the first `/api/live` request and closed after `IDLE` s without one; feed updates are deep-merged (`merge`: dict updates to lists address items by index). `Position.z`/`CarData.z` need an F1 TV subscription token (the feed silently omits them otherwise): sign-in is MultiViewer's (in the desktop app, `desktop.py` does it in a window of its own): the viewer's Connect F1 TV popover (`multiviewer.js`) gives a bookmarklet that, clicked on formula1.com after signing in there, reads F1's script-readable `login-session` cookie (`.formula1.com`, `{data: {subscriptionToken}}`) and returns to `/#f1tv=<token>`; `app.js` keeps it in sessionStorage (this tab only) and `util.js` `tvHeaders` sends it as `X-F1-Token`; `f1auth.py` only checks expiry; the server stores nothing (the live connection keeps the last poller's token in memory, and one F1 rejects is not reused); `hasGps` falls back to mini-sector placement once samples stop for 5 s and the token goes as Bearer on negotiate + websocket; the .z topics are inflated and kept as `Position`/`CarData` with the last `BUFFER` s of samples, which `live.js` `liveGps`/`gpsAt`/`liveCar` interpolate ~1.8 s behind the feed. `TimingStats` feeds the live tower's SPEED TRAP column.
- Live feed recorder (`live.py`): `LIGHTSOUT_LIVE_RECORD=1` appends every feed message to `.cache/live/<utc date>.jsonl`; `LIGHTSOUT_LIVE_PLAY=<file>` plays one back in place of F1's socket (`LIGHTSOUT_LIVE_SPEED` times faster), for working on live features between weekends. The feed is only connected while something polls `/api/live`, so keep the live view open to record. `jolpica.py` `calendar_ics`: `/api/calendar/{year}.ics`, every session with a time, in UTC.
