# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
uv sync                                    # install deps (livef1==1.2.11, fastapi, uvicorn)
.venv/Scripts/python src/server.py         # run app at http://127.0.0.1:8086
.venv/Scripts/python tests/test_server.py  # tests (plain asserts, no pytest)
node tests/test_live.mjs                   # live car-placement logic
node tests/test_telemetry.mjs              # derived HUD telemetry (g-forces, tyres, ERS, DRS zones)
node tests/test_sim.mjs                    # race simulation physics (aero, DRS, tyres, full race)
node tests/test_player.mjs                 # player driving (steering, TC/ABS, gearbox) and AI racecraft
node tests/test_circuits.mjs               # auto aero trim, elevation grade, banking
node tests/test_trace.mjs                  # distance-resampled lap telemetry, Δt, engineer insights, trace plot smoke test
node tests/test_whatif.mjs                 # Strategy Lab what-if model (baseline exactness, optimiser, traffic, SC stops)
node tests/test_multiviewer.mjs            # F1 TV overlay timing (session names, telemetry lookup, lights-out sync)
node tests/test_lanes.mjs                  # lap-timing replay lanes (two-column grid, passing without overlap)
node tests/test_drivers.mjs                # Drivers tab season/career tallies (wins, podiums, poles, starts)
```

## Architecture

F1 web app: FastAPI backend in `src/` plus vanilla-JS ES modules in `src/static/` (served at `/static`, no build step).

Backend modules:
- `server.py`: routes. Big payloads (replay, telemetry, live) go out through `raw_json`, skipping FastAPI's slow `jsonable_encoder`. Table endpoints all return `{columns, data, total}` (capped at `MAX_ROWS`), which the data explorer renders generically. `race_info()` (Jolpica race row incl. circuit lat/long) feeds the track and replay routes.
- `jolpica.py`: Jolpica via livef1's bundled `jolpica_client`. `JOLPICA` maps each kind to a query method and the JSON path to one row; `jolpica_fetch` pages through the 100-row limit; `races(year)` is the cached season race list (`race_info`, the circuit selector, elevation, session list; Jolpica allows ~500 req/h). Past seasons and races over 3 days old go through `SETTLED`, a basef1 client with a disk cache (`.cache/jolpica.sqlite`); the rest through livef1's client (5 min in-memory cache).
- `tracks.py`: outlines from MultiViewer (`MV_KEYS` maps Jolpica circuitId -> MultiViewer key; same coordinate system as OpenF1 car positions), else the elevation's OpenF1 lap (`lap_track`, `source: "openf1"`: Madring, Sepang; no corner numbers), else nearest GeoJSON circuit by lat/long (local metres, unknown start/direction). `circuits.js` `f1Coords` tells the first two apart from GeoJSON. `WIDTHS` adds an approximate track width (m) per circuit. `_clean_loop` drops sub-metre duplicate points and the tail where MultiViewer's lap overlaps its start (both made false hairpins). Track dicts carry `circuitId` and MultiViewer `pitLoss`.
- `replay.py`: `mode: "gps"` for 2023+ from OpenF1 (location resampled to a 0.5 s grid, event feeds sorted by time for binary search in the browser; finished sessions cached in `.cache/replay/{session_key}.json` — delete these after changing the payload format; every cache file goes through `save()` (atomic tmp + replace), and `REPLAY_LOCKS` makes a second request for a session being built wait for it). `mode: "laps"` for 1996+ races from Jolpica cumulative lap times. OpenF1's free tier is ~30 req/min; a GPS replay costs ~30 requests. While any session is live OpenF1 answers 401 to everything (`OpenF1Locked`): season meetings/sessions lists are kept in `.cache/openf1/` as a fallback, `/api/season` falls back to livef1's table, `/api/replay` answers 409 `LIVE_NOW` when the live feed is running that session (replay.js then opens the live view). `server.py` `warm_up` (a background thread at start-up, `__main__` and the f1-test launch config) fetches what the default page asks for on parallel threads (season list, this season's calendar and sessions, the latest race's track/geo/elevation/results: 0.5-2.5 s each cold, which the page used to wait on one after another) and builds that race's replay, so the default race doesn't wait ~40 s on first ▶. `/api/telemetry` takes the replay's `start`/`duration` so the replay isn't rebuilt per driver. `elevation()` (`/api/elevation/{year}/{round}`): OpenF1 location z (decimetres) on a fast race lap at that circuit (2023+), cached in `.cache/elevation/{circuitId}.json`. `/api/circuit/{circuitId}` gives the latest past race there (the circuit selector simulates it). `/api/geo/{year}/{round}`: the circuit's real outline in local metres (`tracks._geo_track`, GeoJSON) for georeferencing the satellite ground.
- `f1tv.py`: F1 TV, MultiViewer-style. `/api/f1tv/{year}/{round}`: the weekend's videos from the public catalogue search (`filter_Meeting_Name`, falling back to a 6-letter name stem when F1 TV names the meeting differently, e.g. "Malaysia"; 404 = no results; registered after the routes below or it catches them). `/api/f1tv/channels/{id}`: feeds + driver onboards (`additionalStreams`; INTERNATIONAL goes out as channelId null, the content's own feed, since 2024-and-older races refuse it by channelId). `/api/f1tv/play/{id}?channel=`: `CONTENT/PLAY` with the caller's subscription token (`X-F1-Token` header, see `live.py`) as `ascendontoken`, giving a signed DASH manifest (replays: no DRM; the CDN allows localhost origins) that `multiviewer.js` plays with shaka-player (`shaka-player.compiled.js` from jsDelivr, pre-loaded when the Stream page opens) under our own control bar (`tvcontrols.js`: seek with buffered range, ±10 s, volume, speed, captions, PiP, tile fullscreen, k/space/←/→/m/f keys). Start-up tuning in `load`: `manifest.dash.ignoreMinBufferTime` (F1 TV says minBufferTime 30 s, which held the first frame for ~6 × 5.8 s segments: 12 s → 2 s), `player.load(url, startTime)` so a joining tile doesn't fetch the session's start, `abr.defaultBandwidthEstimate` from `navigator.connection`, and the main feed's play request sent alongside the channel list. 4K: `play(..., uhd=True)` sends `x-f1-override-video-stream: HDR_UHD_DASH` (the header F1 TV's web player's developer settings use), (only 2025+ videos have 4K rights; older ones refuse it, and `play` retries in HD, where they come back as HLS H.264 up to 1080p), which adds 1620p/2160p50 (HEVC Main10, 15.4 Mb/s, main feed only, no DRM on replays); the viewer's 4K switch also sets `preferredVideoCodecs: ['hvc1.2']`, since shaka keeps one video set and otherwise picks the cheaper HEVC Main one (max 1620p), and forces 2160p on the feeds that have it (`hasUhd`: INTERNATIONAL, F1 LIVE; tracker, data and onboards stop at 1080p): `abr.restrictions.minHeight` 2160 before load, then `lock4k` selects it with ABR off; `.mvtile.uhd` shows a 4K badge. Several 4K tiles (measured: 3 x 2160p50 + an onboard, 0-0.1 % frames dropped): non-4K tiles keep ABR `restrictToElementSize` in 4K mode, 4K tiles keep `bufferBehind` 12 s (not 30), the telemetry overlay only touches the page when its 0.5 s sample changes and is placed on the picture by CSS container units (`.mvtel`, assumes 16:9) instead of reading tile sizes every frame, and opening the viewer closes the other panels (`f1:panel`) and stops the 3D stage behind it (`covered()`). Beyond that it's bandwidth: ~15.4 Mb/s per 4K stream. The button disables itself where `mediaCapabilities.decodingInfo` says HEVC Main10 2160p50 can't be decoded (Firefox, Chrome without GPU HEVC). The viewer opens on one stream; ＋ Add stream (popover of feeds + driver cards) adds any number, laid out as a near-square grid or ⤢ main stream + side column (`.mvgrid.spot`); the clicked tile has the sound and is what ⟲ Sync all / ⏯ All follow; a new tile starts at the selected tile's time and catches up once playing. Each tile's ⚙ lists every rendition (`renditions`: resolution, bitrate, codec; shaka only offers the codec family the browser plays) and audio track (commentary languages, `fx` = track sound, `tea` = team radio on onboards; all 192 kb/s stereo), with ABR `restrictToElementSize` on Auto; `/api/f1tv/account` says whether the caller's token is a live subscription, never the token. `/api/f1tv/telemetry/{year}/{round}/{driver}?session=` (`replay.session_telemetry`: the whole session ±, cached under its own `_tv` tag since `telemetry()`'s cache ignores the start) feeds each tile's see-through overlay (`.mvtel`). F1 TV replays have no clock (static DASH from 0 s, no prft/PDT in any platform variant), so `multiviewer.js` puts video 0 s at F1 TV's scheduled start − `LEAD` (308 s, measured on the 2026 US GP race) plus a per-video offset in localStorage, set with the header's ±1/10 s nudges or 🏁 Lights out (`launchAt`: first launch after 20 s stood still); tested in `tests/test_multiviewer.mjs`. Live = inside the session's scheduled times + 30 min (F1 TV's `state` field is stale); live streams are Widevine, their license header (`entitlementtoken`) is untested.
- `live.py`: free live timing over F1's SignalR Core feed (`/signalrcore`, no login). One background connection, opened by the first `/api/live` request and closed after `IDLE` s without one; feed updates are deep-merged (`merge`: dict updates to lists address items by index). `Position.z`/`CarData.z` need an F1 TV subscription token (the feed silently omits them otherwise): sign-in is MultiViewer's: the viewer's Connect F1 TV popover (`multiviewer.js`) gives a bookmarklet that, clicked on formula1.com after signing in there, reads F1's script-readable `login-session` cookie (`.formula1.com`, `{data: {subscriptionToken}}`) and returns to `/#f1tv=<token>`; `app.js` keeps it in sessionStorage (this tab only) and `util.js` `tvHeaders` sends it as `X-F1-Token`; `f1auth.py` only checks expiry; the server stores nothing (the live connection keeps the last poller's token in memory, and one F1 rejects is not reused); `hasGps` falls back to mini-sector placement once samples stop for 5 s and the token goes as Bearer on negotiate + websocket; the .z topics are inflated and kept as `Position`/`CarData` with the last `BUFFER` s of samples, which `live.js` `liveGps`/`gpsAt`/`liveCar` interpolate ~1.8 s behind the feed. `TimingStats` feeds the live tower's SPEED TRAP column.
